# Role & Permission Matrix

Generated by querying the live `role_permissions` and `role_meta` tables directly — not transcribed from migration SQL. The DB is authoritative at runtime (`backend/src/modules/rbac/rbac.service.ts`); permissions are editable per-role via `/settings/rbac` and `/settings/roles`, so this snapshot can drift from the original seed migration over time. Regenerate with:

```sql
SELECT role, label, description FROM role_meta ORDER BY role;
SELECT permission, role, granted FROM role_permissions ORDER BY permission, role;
```

**Important runtime caveat**: `super_admin` is hardcoded to hold **every** permission regardless of its DB rows (`rbac.service.ts:47`, `map['super_admin'] = new Set(PERMISSIONS)`), and its own permission-update endpoint explicitly rejects attempts to change it (`rbac.service.ts:132-133`, throws 403 "super_admin permissions cannot be changed"). Its `✓`/`✗` cells below reflect the DB rows as stored, which happen to already be all-`true` for this install — but even if they weren't, the application would still grant super_admin everything.

## Reading the matrix by role

- **super_admin** — every permission, unconditionally (see caveat above).
- **sales_manager** — full control of leads, opportunities (including closing deals), follow-ups, customers, referrals, and all analytics; `revenue.read` only (cannot manage or export revenue); no `campaigns.manage`, no `users.manage`.
- **sales_executive** — day-to-day lead and opportunity work (create/update, including PII access) and follow-ups; cannot assign/delete/export leads, cannot close opportunities, cannot manage customers (read-only), no pipeline-wide view, no revenue or analytics access at all.
- **marketing_manager** — campaigns and referrals, full analytics (including financial); can see leads and the full pipeline but cannot create/edit them; no opportunities, no customers, no revenue.
- **finance** — full revenue control (read/manage/export) and full analytics; read-only on opportunities/customers/pipeline; **no leads access whatsoever**.
- **read_only_analyst** — read-only across leads, pipeline, opportunities, customers, revenue, and analytics (excluding `analytics.financial`); no create/update/manage permission anywhere.

Only `users.manage` is held exclusively by `super_admin` — this is also the permission gating every `/settings/*` page in the frontend (LLM config, RBAC admin, General Settings, Security, user management), so in practice only super_admin can reach Settings today, even though the route guard technically checks the permission rather than the role name directly.
